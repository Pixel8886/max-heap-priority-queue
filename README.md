# Priority Queue (Max-Heap)

Реализация приоритетной очереди на основе бинарной кучи (Max-Heap) на Python.

## Описание

Приоритетная очередь хранит элементы с приоритетами и извлекает элемент с наивысшим приоритетом. Используется бинарная куча, где максимальный элемент всегда в корне.

При равных приоритетах работает FIFO: кто раньше добавлен, тот раньше извлечён.

## Как это работает

### Бинарная куча

Куча хранится в списке, но логически это двоичное дерево. Для индекса `i`:
родитель `(i - 1) // 2`, левый ребёнок `2 * i + 1`, правый ребёнок `2 * i + 2`.

Свойство Max-Heap: родитель больше или равен детям. Поэтому максимум всегда в корне (индекс 0).

### Хитрость с минусом

Python не имеет встроенного Max-Heap, только Min-Heap. Чтобы получить Max-Heap, приоритет хранится с минусом. Приоритет `10` становится `-10`, приоритет `5` становится `-5`. Теперь `-10` меньше `-5`, и Python ставит его наверх, что соответствует исходному приоритету `10`.

### FIFO при равных приоритетах

Элемент хранится как кортеж `(-priority, counter, value)`. Счётчик `counter` растёт при каждой вставке. Если приоритеты равны, Python сравнивает счётчики: меньший счётчик (добавленный раньше) получает более высокий приоритет.

## Методы класса

| Метод | Описание | Сложность |
|-------|----------|-----------|
| `insert(priority, value)` | Добавляет элемент с приоритетом | O(log n) |
| `extract_max()` | Извлекает элемент с максимальным приоритетом | O(log n) |
| `peek_max()` | Возвращает максимум без извлечения | O(1) |
| `change_priority(old_value, new_priority)` | Меняет приоритет элемента | O(n) |
| `__len__()` | Количество элементов | O(1) |
| `is_empty()` | Проверка на пустоту | O(1) |

### Детали реализации

**insert** — элемент добавляется в конец, затем поднимается вверх (`_sift_up`).

**extract_max** — корень запоминается, последний элемент встаёт в корень и опускается вниз (`_sift_down`).

**peek_max** — возвращает значение из корня.

**change_priority** — перебирает элементы (O(n)), заменяет приоритет и восстанавливает кучу. Применяются обе операции: `_sift_up` и `_sift_down`, так как новый приоритет может быть выше или ниже старого.
